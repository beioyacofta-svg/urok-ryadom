# Семейные аккаунты API

## Что изменилось для пилотных продаж

API поддерживает несколько семей. Каждая семья получает собственный `familyId`, набор детских профилей и отдельные логины родителя и детей. Браузер использует `familyId` как пространство локального хранения, поэтому переписки разных семей на одном устройстве не смешиваются.

Самостоятельной регистрации пока нет: аккаунты закрытого пилота создаются вручную в защищённом `/etc/urok-ryadom-accounts.json`.

## Формат конфигурации

Безопасный пример без настоящих паролей находится в `accounts.example.json`.

- `families[].id` — непубличный стабильный идентификатор семьи;
- `families[].profiles` — профили детей;
- `accounts[].id` — логин пользователя;
- `accounts[].familyId` — семья, к которой относится аккаунт;
- `role` — `parent` или `child`;
- `profileKeys` — профили, доступные родителю;
- `profileKey` — единственный профиль детского аккаунта;
- `salt` и `passwordHash` — соль и scrypt-хеш в Base64.

Настоящий файл аккаунтов нельзя добавлять в Git. Он остаётся системным credential-файлом с ограниченными правами.

## Порядок безопасного обновления

1. Сделать резервную копию действующего файла аккаунтов на сервере.
2. Сначала обновить `server.mjs` и перезапустить API.
3. Проверить `/health`, вход текущей семьи и отправку текстового вопроса.
4. Добавить тестовую семью в защищённый конфиг и перезапустить API.
5. Проверить родительский и детский вход тестовой семьи.
6. Только после этого публиковать новый `index.html` и `sw.js`.

Backend сохраняет совместимость со старой конфигурацией одной семьи: если массива `families` нет, профили собираются из детских аккаунтов.

## Границы текущего пилота

- история занятий хранится локально на устройстве до 30 дней;
- настройки профилей на другом устройстве автоматически не появятся;
- API не хранит тексты заданий и ответы;
- нет самостоятельной регистрации, восстановления пароля и оплаты;
- семейные аккаунты создаёт администратор пилота;
- раздел «История» показывает активность, а не педагогическую оценку знаний.

Перед открытой продажей нужны серверное хранилище семей, подтверждаемое согласие родителя, политика обработки данных, восстановление доступа, управление подпиской и журнал административных действий.
